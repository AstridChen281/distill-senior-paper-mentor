# 学习有证据的研究叙事

以用户提供的论文卡片和 `library/writing-profile.md` 为证据，学习结构、用语、段落功能、例子与图表以及论证闭合。公开模板不预设某个人的风格或任何特定论文的写法。

## 先重建当前研究

暂定主线：`具体场景的要求 → 现有方法遗漏什么 → 可检验问题 → 核心洞察 → 方法为何回应要求 → 实验支持什么 → 剩余边界`。每项都来自用户实际稿件或已确认的信息；缺洞察或结果就指出缺口。

根据稿件已有证据选择组织方式：能力与评测驱动、受控现象与发现驱动、现实约束驱动、现有范式的缺口驱动、数据资源与使用协议驱动。参考档案提供候选写法，用户研究的证据决定采用哪种。不要编造先导发现，不把工程改进包装为已经证明的机制。

## 从结构落到实际文本

建立摘要、引言、方法与实验的功能图。每段应承担明确职责，相邻段落应有真实逻辑关系。方法名出现前，读者应理解问题、缺口和设计要求。方法模块逐项回应要求，实验按要回答的问题安排。贡献列表总结已建立的论证。

运行例子用来解释问题或设计；图表用于展示现象、区分方案、解释流程或回答实验问题。示意例子标明是示意，不能冒充真实样本。只读过图注时，不声称检查过图片。检验引言的问题是否在实验中被回答。

术语先定义再稳定使用，减少同义词造成的概念漂移。过渡词表达实际因果、对比、递进或限制。保留实验范围和限定语，不把“结果支持”改成“普遍证明”。学习表达的功能，不复制原句，不机械模仿修辞。

给建议时交付主线、断点和优先重排；直接改稿时执行实际重写并解释段落职责变化。复核数字、贡献、引用和结论范围，以及哪些主张仍需补证据。
